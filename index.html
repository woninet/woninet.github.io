Network Monitoring

A local network monitoring system that detects network hosts, tracks their availability, and measures latency, packet loss, and jitter. It continuously collects metrics and evaluates configurable alert rules in real time.

Built for your local network

Accurate host detection, continuous metrics, and alerts you can tune, from a single Python package.

🔍

ARP + ICMP Host Detection

Distinguishes real devices from nonexistent IP addresses and filters out Wi-Fi ARP-delay noise.

🔔

Alert Engine

Evaluates real-time alert rules, such as latency thresholds, against the metrics it collects.

⚡

Threaded Collectors

Sends ICMP probes concurrently using a configurable number of worker threads.

🗃

PostgreSQL & SQLite

Persists devices, recorded metrics, alert states, and alert events in a custom SQL database.

Database Access from the CLI

Accepts a positional argument for easier access to the database straight from the command line.

Diagnostic Manager

Preserves, collects, and display issues to user through the dashboard UI. Resolve basic configuration issues automatically.

Metrics and alert rules

Three metrics are tracked for every host. Each can drive its own alert rule.

MetricUnitAlert threshold behavior
latencymillisecondsTriggers when latency exceeds the threshold.
jittermillisecondsTriggers when jitter exceeds the threshold.
packet_losspercent (0.0 to 100.0)A threshold of 0.0 triggers on any packet loss.

Each rule also sets consecutive_checks, the number of consecutive evaluations required before the alert state changes. Higher values reduce false positives.

Get started in minutes

Requires Python 3.12 or later and raw-socket access for ARP and ICMP probing.

Linux (recommended)

Install from PyPI in a virtual environment and grant cap_net_raw to the interpreter, avoiding the need to run as root.

python3 -m venv --copies venv
source venv/bin/activate
pip install woninet
sudo setcap cap_net_raw=eip venv/bin/python3
woninet --help

Without the capability, Woninet falls back to the system ping command. Create the environment without --copies in that case.

Docker (Linux only)

Clone the repository and run the build script. It starts the stack and prints the device's private IP address.

chmod +x build_docker.sh
sudo ./build_docker.sh

Open the printed address in your browser using the default port 8080.

From source

Create the virtual environment outside the project directory to avoid flat-layout discovery errors.

git clone https://github.com/woninet/woninet
cd woninet
python3 -m venv --copies ../venv
source ../venv/bin/activate
pip3 install .
sudo setcap cap_net_raw=eip ../venv/bin/python3
woninet --version

Running with sudo instead of granting the capability is possible but discouraged for security reasons.

Simple JSON configuration

Alert rules and monitoring settings live in a single config.json loaded at startup.

{
    "monitoring": {
        "arp_noise_limit": 300.0,
        "max_workers": 4
    },
    "database": {
        "type": "sqlite",
        "path": "woninet.db"
    },
    "target_ip_list": [
        "192.168.1.1", "192.168.1.10", "192.168.1.20-30"
    ],
    "alert_rules": [
        {
            "metric": "latency",
            "threshold": 100,
            "consecutive_checks": 3
        },
        {
            "metric": "packet_loss",
            "threshold": 0.0,
            "consecutive_checks": 1
        },
        {
            "metric": "jitter",
            "threshold": 40.0,
            "consecutive_checks": 3
        }
    ]
}

Settings at a glance

  • arp_noise_limit: latency threshold in milliseconds used to filter ARP resolution noise. Set to 0 to disable filtering.
  • max_workers: maximum number of worker threads used to send ICMP pings.
  • database.type: sqlite or postgresql.
  • database.path: a file path for SQLite, or a connection URL for PostgreSQL.
  • target_ip_list: a single address, a list of addresses, or a range such as 192.168.1.1-100.
  • alert_rules: a list of rules, each with a metric, threshold, and consecutive_checks.
Using PostgreSQL? Keep credentials out of config.json. Define WONINET_DATABASE_URL in a .env file in the project root; it overrides database.path.

Use --config to load a different file. When installed from PyPI, Woninet creates a default config.json for you.

Platform support

Woninet is developed and tested on Linux.

PlatformProbing methodPrivileges
Linuxicmplib (recommended) or system ping (fallback)cap_net_raw on the interpreter, or root
macOSUntestedUntested
WindowsUntestedUntested

macOS and Windows have not been tested, so behavior there is not guaranteed. Feedback and bug reports are welcome. Docker deployment is available on Linux only. Monitoring is currently limited to a single /24 subnet.
